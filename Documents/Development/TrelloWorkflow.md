# Trello Workflow

Trello 보드를 프로젝트의 단일 작업 목록(Single Source of Truth)으로 사용한다.
다음에 무엇을 할지에 대한 답은 항상 보드에 있어야 하며, 대화 기록이나 별도 메모로 분산시키지 않는다.

## 리스트 구조

Inbox → Backlog → Doing → Verify → Done 순으로 흐른다.
Icebox는 흐름에 포함되지 않는 보관용 리스트다.

### Inbox
- 작업 중 발견한 항목을 분류 없이 수집한다
- Backlog에서 다음 작업을 꺼낼 때 Inbox를 먼저 분류한다. 각 카드는 Backlog / Icebox / 아카이브로 보낸다

### Backlog
- 하기로 결정한 작업
- 우선순위 순으로 정렬한다. 맨 위의 카드가 다음에 할 작업이다
- 카드 하나의 크기는 커밋 제목 한 줄로 요약되는 수준으로 유지한다
- 분류가 끝나지 않은 카드는 Backlog가 아니라 Inbox에 둔다

### Doing
- 현재 진행 중인 작업
- 최대 2장을 유지한다

### Verify
- 구현은 끝났지만 검증이 남은 작업 (실기 확인, 플레이 검증, CI 결과 대기 등)
- 검증에 실패하면 Doing으로 되돌린다

### Done
- 완료된 작업
- 마일스톤이 끝날 때 일괄 아카이브한다. 삭제하지 않는다

### Icebox
- 학습 주제와 검증되지 않은 아이디어
- 실행 일정에 올리지 않으며, 실행이 결정되면 Backlog로 옮긴다

## 라벨

두 축으로 관리한다.

- **영역:** 무엇에 관한 작업인가 (`Core` / `Game` / `Build` / `Docs`)
- **마일스톤:** 어느 로드맵 구간의 작업인가. 명명은 로드맵을 따른다

마일스톤을 리스트가 아닌 라벨로 두는 것은, 카드가 마일스톤을 넘나들 때 이동이 없고
Backlog 안에서 필터만으로 특정 마일스톤의 목록을 얻을 수 있기 때문이다.

## TODO 주석과 카드의 구분

같은 항목을 코드의 TODO 주석과 카드에 중복해서 두지 않는다.

- **TODO 주석:** 해당 코드를 읽을 때만 의미가 있는 항목
- **카드:** 일정에 올려 추적할 항목

TODO를 일정에 올리기로 결정하면 카드로 승격하고, 주석에서는 제거한다.
